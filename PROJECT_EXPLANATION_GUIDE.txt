PHASE B: DATA CLEANING & SANITIZATION
----------------------------------------------------------------------------------------------------
Lines 74-84:
  - Type Casting & Error Coercion:
    `df["ts"] = pd.to_datetime(df["ts"], errors="coerce")` -> Converts string dates to datetime objects.
    `df["GlucoseCGM"] = pd.to_numeric(df["GlucoseCGM"], errors="coerce")` -> Invalid string entries become NaN.
    `df["HR"] = pd.to_numeric(df["HR"], errors="coerce")` -> Invalid heart rate entries become NaN.
Lines 86-88:
  - `df = df.dropna(subset=["ts", "PtID"]).copy()`: Drops records with missing timestamps or missing patient identifiers because time-series tracking requires exact timestamps and patient identity.
Lines 90-94:
  - `df.loc[df["GlucoseCGM"] <= 0, "GlucoseCGM"] = np.nan`: Physically impossible non-positive glucose values (<=0) are marked as missing NaN rather than distorting numerical gradients.
Lines 96-98:
  - `df = df.sort_values(["PtID", "ts"]).reset_index(drop=True)`: Sorts each patient's sensor records in strict chronological order.
  * What to explain to Sir: "Sir, physiological sensors frequently suffer from transient sensor disconnects or dropout. Rather than treating 0 as a valid glucose level, we explicitly sanitize the input so sensor errors do not mislead the model."

PHASE C: CIRCADIAN FEATURE ENGINEERING (CYCLICAL TIME ENCODING)
----------------------------------------------------------------------------------------------------
Lines 100-112:
  - `minutes = df["ts"].dt.hour * 60 + df["ts"].dt.minute`: Extracts the minute-of-day (0 to 1439).
  - `df["time_sin"] = np.sin(2 * np.pi * minutes / 1440)`: Cyclical sine component.
  - `df["time_cos"] = np.cos(2 * np.pi * minutes / 1440)`: Cyclical cosine component.
  * What to explain to Sir: "Glucose sensitivity fluctuates dramatically throughout a 24-hour cycle (e.g., dawn phenomenon, night fasting). If we used linear hour 0 to 23, the model would think 23:59 and 00:01 are far apart. Using sin/cos trigonometrical projection keeps midnight continuous."

----------------------------------------------------------------------------------------------------
PHASE D: CHRONOLOGICAL PATIENT-WISE SPLIT (PREVENTING DATA LEAKAGE)
----------------------------------------------------------------------------------------------------
Lines 133-175:
  - Function: `split_data(df)`
  - Iterates over each patient (`df.groupby("PtID")`).
  - Line 156-157: `train_end = int(n * 0.70)`, `val_end = int(n * 0.85)`
  - Splits each patient's timeline sequentially: 70% Train, 15% Validation, 15% Unseen Test.
  * What to explain to Sir: "Sir, random shuffling would cause severe lookahead data leakage in medical time-series. We preserve strict chronological order within each patient's data, ensuring future points never leak into the training past."

----------------------------------------------------------------------------------------------------
PHASE E: IMPUTATION FROM TRAINING DISTRIBUTION ONLY
----------------------------------------------------------------------------------------------------
Lines 181-201:

  - `group["HR"] = group["HR"].fillna(hr_median)`: Imputes missing heart rate entries across all splits using the pre-computed training median.
  * What to explain to Sir: "We never compute statistics on validation or test sets. The heart rate median is derived purely from training data and then applied downstream."

PHASE F: TEMPORAL SEQUENCE EXTRACTION & GAP VERIFICATION
----------------------------------------------------------------------------------------------------
Lines 225-312:
  - Function: `create_sequences(groups, feature_scaler, target_scaler, fit_scalers)`
  - Lines 285-296: Slides a window of size 12 across patient records.
  - Lines 302-312 (Gap Rejection):
    `gaps = [times[i + 1] - times[i] for i in range(len(times) - 1)]`
    `if not all(pd.Timedelta(0) < gap <= max_gap for gap in gaps): continue`
    Rejects any 12-reading window that spans across a sensor disconnection or overnight interruption (> 5 minutes).
  * What to explain to Sir: "If a patient took off their sensor for 2 hours and put it back on, stitching those readings together would create artificial gradients. Our pipeline detects temporal gaps and discards discontinuous sequence windows."

PHASE I: DUAL-BRANCH HYBRID NEURAL ARCHITECTURE
----------------------------------------------------------------------------------------------------
Lines 383-424:
  - Class `PositionalEncoding(nn.Module)`:
    Generates sinusoidal positional embeddings to retain sequential timestep awareness for attention heads.
Lines 430-490:
  - Class `HybridLSTMTransformer(nn.Module)`:
    * Projection Layer (Line 437): `nn.Linear(4, 64)` -> Expands 4 physical features into 64-dimensional latent embedding.
    * Positional Encoding (Line 441): Adds positional vectors to input latent embeddings.
    * Branch 1 (Lines 446-451): `nn.LSTM(input_size=64, hidden_size=64, num_layers=1, batch_first=True)`
      Extracts sequential momentum and historical rate-of-change.
    * Branch 2 (Lines 454-468): `nn.TransformerEncoderLayer(d_model=64, nhead=4, dim_feedforward=256, activation='gelu')`
      Multi-head self-attention to capture cross-timestep dependencies.
    * Fusion Network (Lines 471-489):
      Concatenates final timestep of both branches (`64 + 64 = 128` features).
      Linear(128 -> 64) -> ReLU -> Dropout(0.1) -> Linear(64 -> 32) -> ReLU -> Linear(32 -> 1).
Lines 491-525:
  - `forward(x)`: Implements the forward propagation graph.
  * What to explain to Sir: "Sir, LSTMs are effective at sequential Markovian transitions, while Transformers excel at global attention across entire windows. Combining both branches through a multi-stage fusion head gives significantly better predictive fidelity than either architecture alone."

Lines 707-722:

  - Learning Rate Scheduler: `ReduceLROnPlateau(patience=2, factor=0.5)` (Halves learning rate when validation loss plateaus).
Lines 532-571:
  - Function `train_epoch()`: Forward pass -> Loss computation -> `loss.backward()` -> `torch.nn.utils.clip_grad_norm_(max_norm=1.0)` (prevents exploding gradients) -> `optimizer.step()`.

  - Epoch loop (20 epochs) with early stopping patience of 5 epochs. Saves checkpoint only when validation loss hits a new historical minimum.
  * What to explain to Sir: "Gradient clipping stabilizes Transformer attention backpropagation, while early stopping and ReduceLROnPlateau prevent overfitting."

    2. Validates schema and extracts the last 12 readings (Lines 212-243).
    3. `generate_forecast(history, steps)` (Lines 245-263):
       Autoregressive multi-step rollout:
       - 6 steps   -> 30-minute forecast horizon.
       - 12 steps  -> 60-minute forecast horizon.
       - 24 steps  -> 120-minute (2 hour) forecast horizon.
    4. Clinical Risk Stratification (Lines 269-281):
       - Spike > +40 mg/dL: High Glucose Spike (Reactive Hypoglycemia risk).
       - Spike > +20 mg/dL: Moderate Rise.
       - Drop < -40 mg/dL: Rapid Drop Alert (Immediate Carbohydrate Intake needed).
       - Drop < -20 mg/dL: Gradual Decline.
       - Abs(Delta) <= 20: Clinically Stable.
