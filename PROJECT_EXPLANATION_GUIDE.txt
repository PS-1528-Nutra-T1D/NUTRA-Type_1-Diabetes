1. HIGH-LEVEL PROJECT ARCHITECTURE (THE ELEVATOR PITCH)
----------------------------------------------------------------------------------------------------
"Sir, our project is a real-time Blood Glucose Forecasting system for Type 1 Diabetes (T1D).
Managing T1D requires continuous vigilance to prevent hypoglycemia (life-threatening low blood sugar)
and hyperglycemia (spikes). 

We developed a deep learning architecture that combines:
  1. Recurrent inductive bias (LSTM) to capture sequential blood sugar dynamics.
  2. Multi-Head Self-Attention (Transformer) to capture long-range temporal dependencies and circadian rhythms.
  3. A clinical multi-step autoregressive forecasting pipeline to predict glucose levels 30 min, 60 min,
     and 120 min into the future.
  4. An end-to-end cloud deployment: FastAPI on Render + Clinical Web UI on Netlify."

STEP 1: THE DATASET & FEATURE ENGINEERING
--------------------------------------------------
File: model_training_and_graphs/lstmtransformer.py (Lines 35 - 126)
What to show:
  - Input Columns: `GlucoseCGM` (Continuous Glucose Monitor, mg/dL) and `HR` (Heart Rate in bpm).
  - Window Size: WINDOW_SIZE = 12 (12 consecutive readings = 60 minutes of history at 5-min intervals).
  - Time-of-day features:
      time_sin = sin(2 * pi * minutes / 1440)
      time_cos = cos(2 * pi * minutes / 1440)
What to say:
  "Sir, glucose dynamics vary drastically based on human circadian rhythm (e.g., dawn phenomenon, meal times).
   Instead of just raw values, we projected the timestamp into cyclical sine and cosine angles so the network
   understands 24-hour periodicity."


STEP 2: THE HYBRID NEURAL NETWORK ARCHITECTURE
--------------------------------------------------
File: model_training_and_graphs/lstmtransformer.py (Lines 425 - 528)
Also in: backend/app.py (Lines 60 - 130)
What to show:
  Show class `HybridLSTMTransformer(nn.Module)`:
  - Linear Projection: Projects the 4 input features into 64-dimensional latent space.
  - Positional Encoding: Injects order information for transformer attention.
  - Branch 1 (LSTM): nn.LSTM(input_size=64, hidden_size=64, num_layers=1, batch_first=True)
  - Branch 2 (Transformer): nn.TransformerEncoderLayer(d_model=64, nhead=4, dim_feedforward=256, activation='gelu')
  - Fusion Layer: Concatenates lstm_features + transformer_features (128-dim) -> Linear -> ReLU -> Linear(32) -> Output(1)
What to say:
  "Sir, standalone LSTMs struggle with long horizons, while standard Transformers lack the natural recurrence
   property inherent in physiological streams. We designed a dual-branch hybrid:
   - Branch 1 (LSTM) tracks short-term momentum and rate-of-change.
   - Branch 2 (Transformer with 4 Attention Heads) attends across the entire 1-hour window.
   - A multi-layer fusion head merges both representations into a single glucose prediction."

4. QUICK RECAP TABLE FOR SIR'S COMMON QUESTIONS
----------------------------------------------------------------------------------------------------
Question: "Why did you use PyTorch?"
Answer:   "PyTorch allows dynamic tensor graphs and explicit model architecture customization for combining
          LSTM layers and Transformer Encoder layers."

Question: "Where are the model weights stored?"
Answer:   "`backend/hybrid_lstm_transformer.pth`. The file is 601 KB, containing both the trained weights
          and the exact mean/standard-deviation normalization tensors to guarantee inference consistency."

Question: "How do you avoid latency or server crashes on Render?"
Answer:   "We compiled PyTorch CPU wheels (`whl/cpu`) and eliminated heavy redundant scikit-learn model files,
          keeping memory footprint well under Render's 512MB RAM limit."
